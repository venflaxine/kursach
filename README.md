# Локальный антиплагиат — анализатор сходства текстов на N-граммах

Курсовой проект на **C++17 и Qt 6 Widgets**. Программа сравнивает два текста локально: не подключается к внешним сервисам и не отправляет содержимое документов в интернет.

## Возможности

- Ввод двух текстов прямо в окне приложения.
- Загрузка локальных текстовых файлов `.txt` и `.md` в кодировке UTF-8.
- Два вида N-грамм: последовательности слов и последовательности символов.
- Выбор размера N от 1 до 10.
- Две метрики: коэффициент Жаккара и косинусное сходство по частотам N-грамм.
- Настройки регистра, пунктуации и пробельных символов.
- Процент сходства, сводная статистика и таблица совпавших N-грамм.
- Экспорт текстового отчёта в UTF-8.
- Проверки входных данных и лимиты на размер текста/файла.
- Автотесты алгоритма на Qt Test и CTest.

## Что такое N-грамма

N-грамма — это последовательность из N соседних элементов.

Например, для текста `"кот ловит мяч"` при N = 2 словесные N-граммы будут:

1. `кот ловит`
2. `ловит мяч`

Для символьных N-грамм при N = 3 текст `"мама"` даст `мам` и `ама`.

### Метрики

**Коэффициент Жаккара** сравнивает множества уникальных N-грамм:

`J(A, B) = |A ∩ B| / |A ∪ B|`

Он не учитывает, сколько раз одна и та же N-грамма повторяется.

**Косинусное сходство** сравнивает векторы частот N-грамм:

`cos(A, B) = (A · B) / (||A|| × ||B||)`

Оно учитывает, сколько раз каждая N-грамма встречается в каждом тексте.

Обе метрики возвращают значение от 0 до 1; интерфейс показывает его в процентах. Если тексты после нормализации имеют одинаковый набор N-грамм для Жаккара или одинаковые частоты для косинусной метрики, результат будет 100%.

## Важные ограничения

- Процент сходства **не является доказательством плагиата**. Он показывает только сходство текста при выбранных настройках.
- Цитаты, шаблонные формулировки, короткие тексты и общая терминология могут давать высокий процент.
- Низкий процент не доказывает отсутствие заимствования: перефразирование может сильно снизить лексическое сходство.
- Интервалы «низкое / умеренное / высокое / очень высокое» в интерфейсе условные и используются только для демонстрации.
- В режиме слов пунктуация и пробелы разделяют слова. Флажки игнорирования пунктуации и пробелов применяются к режиму символьных N-грамм.
- Каждый текст ограничен 200 000 UTF-16 кодовыми единицами; размер загружаемого файла — 2 MiB. Поддерживаются текстовые файлы UTF-8.

## Требования

- Qt 6.3 или новее, модуль **Qt Widgets**.
- CMake 3.21 или новее.
- Компилятор с поддержкой C++17.
- Для запуска тестов также нужен модуль **Qt Test**.

Удобнее всего открыть проект через Qt Creator, установив Qt 6 и комплект компилятора, соответствующий выбранному Kit (например, MSVC или MinGW на Windows).

## Сборка через Qt Creator

1. Установите Qt 6 через официальный Qt Online Installer. Выберите Qt 6, комплект Desktop для вашего компилятора и CMake.
2. Запустите Qt Creator.
3. Выберите **File → Open File or Project…** и откройте `CMakeLists.txt` в корне проекта.
4. Выберите совместимый Desktop Kit и дождитесь конфигурации CMake.
5. Соберите проект кнопкой **Build**.
6. Запустите конфигурацию `local_antiplagiarism`.

Если Qt Creator сообщает, что Qt не найден, проверьте выбранный Kit и наличие модуля Qt Widgets. Компилятор и Qt должны быть собраны для одного и того же комплекта (например, нельзя смешивать MinGW-kit с MSVC-kit).

## Сборка из командной строки

Команды запускаются из корневой папки проекта в терминале, где CMake видит установленный Qt 6:

```bash
cmake -S . -B build -DBUILD_TESTING=ON
cmake --build build --config Release
ctest --test-dir build -C Release --output-on-failure
```

Если CMake не находит Qt, укажите путь к папке соответствующего Qt-комплекта через `CMAKE_PREFIX_PATH`. Конкретный путь зависит от вашей установки, операционной системы и компилятора.

На Linux имя исполняемого файла обычно `local_antiplagiarism`; на Windows это будет `local_antiplagiarism.exe` в каталоге сборки, возможно внутри `Release` или `Debug`.

## Проверки, реализованные в коде

- Пустой первый или второй текст.
- Пустые строки, состоящие только из пробелов и переносов.
- N вне диапазона 1–10.
- Слишком длинный текст.
- Слишком мало слов/символов для выбранного N после нормализации.
- Ошибка открытия или чтения файла.
- Файл больше 2 MiB.
- Ошибочная UTF-8 последовательность.
- Длина загруженного текста выше лимита.
- Отказ сохранять отчёт, если сравнение не завершилось успешно.
- Проверка ошибки при открытии/записи отчёта.
- Обработка одинаковых текстов, различия регистра, русского текста, пунктуации, пробелов, Жаккара и косинусной метрики тестами.

## Пример ручной проверки

1. Откройте `examples/text_a.txt` и `examples/text_b.txt` в блокноте.
2. Скопируйте содержимое в поля A и B или загрузите файлы кнопками.
3. Выберите режим «По словам», N = 2, метрику Жаккара.
4. Нажмите «Сравнить тексты» и проверьте процент и список общих фраз.
5. Переключите метрику на косинусную и сравните результат.
6. Нажмите «Сохранить отчёт…» и проверьте созданный `.txt`.

## Публикация на GitHub

1. Создайте пустой репозиторий на GitHub, например `local-text-similarity`. Для простоты не добавляйте к нему README, лицензию или `.gitignore`, потому что они уже есть в этом проекте.
2. Откройте терминал в корневой папке проекта.
3. Выполните команды ниже, заменив `ВАШ_ЛОГИН` своим логином GitHub:

```bash
git init
git add .
git status
git commit -m "Initial commit: local n-gram text similarity analyzer"
git branch -M main
git remote add origin https://github.com/ВАШ_ЛОГИН/local-text-similarity.git
git push -u origin main
```

Перед `git commit` внимательно проверьте вывод `git status`: не добавляйте личные документы, содержимое курсовых работ других людей, пароли или файлы сборки. В `.gitignore` уже исключён каталог `build/`.

Если Git сообщает, что имя или email не заданы, настройте их один раз:

```bash
git config --global user.name "Ваше имя"
git config --global user.email "адрес, привязанный к GitHub"
```

GitHub обычно не принимает пароль учётной записи в качестве пароля для `git push` по HTTPS. Следуйте экранной авторизации Git Credential Manager или используйте Personal Access Token в качестве пароля, если терминал его запросит. Никогда не вставляйте токен в исходный код или README.

После публикации откройте вкладку **Actions** репозитория: workflow попробует собрать проект и выполнить тесты автоматически.
